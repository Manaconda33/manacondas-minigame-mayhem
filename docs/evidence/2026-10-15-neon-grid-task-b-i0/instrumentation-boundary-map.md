# Task B I0 instrumentation boundary map

**Implementation baseline:** approved Task A runtime commit `692e9424c2cbf15decbb467b230c02c2e10452a0`.

This map was recorded before changing runtime code. It follows the existing render order and counter reset boundaries.

| Boundary                                    | Existing behavior                                                                                                                                                        | Measurement interpretation                                                                                                                                                                |
| ------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `RaceBloom.render` start                    | Saves `renderer.info.autoReset`, sets it to `false`, then calls `renderer.info.reset()` once.                                                                            | This is the per-frame renderer-counter origin. The instrumentation must snapshot counters only; it must not call `reset`.                                                                 |
| Main scene `renderer.render(scene, camera)` | Runs first with ordinary scene materials, fog, background, target, and shadow settings.                                                                                  | Its counter delta is the main scene submission. Shadow-map submissions are included when Three.js performs them inside this render; the API does not split shadow calls from scene calls. |
| Bloom mask `renderer.render(scene, camera)` | Runs with mask materials into the `mask` target; fog/background are removed and shadow updates are disabled.                                                             | Attribute separately to `bloomMask`; it does not trigger new shadow-map updates in this path.                                                                                             |
| Bloom horizontal filter                     | Full-screen triangle rendered to `horizontal`.                                                                                                                           | Attribute its renderer counters to `bloomHorizontal`. Target dimensions come from that render target.                                                                                     |
| Bloom vertical filter                       | Full-screen triangle rendered to `vertical`.                                                                                                                             | Attribute its renderer counters to `bloomVertical`. Target dimensions come from that render target.                                                                                       |
| Bloom final composite                       | Full-screen triangle rendered to the target that was active before bloom (normally the drawing buffer).                                                                  | Attribute to `bloomComposite`; record actual drawing-buffer dimensions for the default framebuffer, otherwise the active target dimensions.                                               |
| Bloom failure recovery                      | Restores original scene/renderer state, releases bloom resources, and redraws the original scene.                                                                        | The existing fallback redraw is a separately named `bloomFallbackScene` stage so it remains visible in reconciliation.                                                                    |
| Motion blur                                 | When active, copies two framebuffer bands, disables auto-clear and auto-reset, and submits one fullscreen render to the default framebuffer. It does not reset counters. | Attribute the shader render as `motionBlurComposite`. Record the two framebuffer copies as copy operations with no renderer draw-call/triangle counter values.                            |
| Whole-frame sample in `KartTimeTrial.frame` | After bloom and motion blur, reads `renderer.info.render` plus memory and drawing-buffer counters.                                                                       | Existing fields remain intact. For instrumented frames, compare the whole-frame draw/triangle totals to stage sums; report any residual and known work outside named stages.              |

## Scope and safety

- Diagnostics are created only for the existing exact `?testRacePerf=1` flag. With the flag off, no observer is attached and no pass-counter snapshots are taken.
- `renderer.info` deltas are observations of submitted work, not distinct objects or unique geometry. The same mesh submitted in main and mask passes counts in each pass.
- Full-screen framebuffer copies are not draw calls. Render-target pixel counts are width × height, not GPU work or bandwidth estimates.
- Existing frame-time samples are CPU-observed frame durations. GPU frame time, true texture bytes, and shadow-caster counts are unavailable.
- Stage snapshots do not modify renderer state, render ordering, quality choices, scene contents, or counter reset behavior.

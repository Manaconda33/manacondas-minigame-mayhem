## C0 outcome

The owner selected Option 1: use the existing `undercity-facade-vent-banks` instanced mesh as the proposed C1 target, with NG-C-PNT-001 (Scratched Painted Metal 01). This records target selection only; it does not authorize material implementation or binary acquisition/commit.

The source pages support the proposed CC0 selections and describe the available map families. The existing Undercity scene has UV-ready, lit, instanced batches that could support a small material A/B without adding a draw call. However, there is no support-only instance mesh: the named industrial architecture batch combines foundations, roof plant units, facade ribs, and loading bays. Applying one material to that batch would change all four categories; isolating only the ribs would require changing the batching or adding a material-selection mechanism.

`undercity-facade-vent-banks` is one separate `InstancedMesh` with 16 instances and a merged housing plus three slats per bank. Its four `BoxGeometry` parts retain UV, normal, position and vertex-color attributes; one `MeshStandardMaterial` draws the batch. Preserve this single batch. Keep the housing/slat color distinction: the base-color texture will multiply the existing vertex colors (`#42505d` housing, `#9ba3b2` slats), so the A/B must review the resulting values and hues at racing distance. No per-instance material or extra draw group is needed for the selected target.

### Chase-camera visibility check

A source-pinned browser fixture used the Task A visual selector at Undercity progress 0.355, Medium quality, eight racers, chase view, 1280×720 CSS viewport at DPR 1.5 (actual drawing buffer 1920×1080). Headless Chromium with SwiftShader reported no page, console, or HTTP errors. From the 16 vent banks, 9 projected into the viewport; only 3 had any target-first hits in a 3×3 ray sample across their projected bounds. The other in-frame samples were blocked mainly by `undercity-wallside-sightline-screens`, with some hits on buildings or a racer. The three partially exposed banks had estimated geometry-box bounds of about 24×15, 51×33, and 22×14 CSS pixels (roughly 36×23, 77×49, and 32×21 drawing-buffer pixels at this DPR). Those boxes overestimate the visible textured area; this is not a pixel-level surface segmentation.

The scene uses linear fog with near 180 and far 650 units. These three bank centers were about 49–80 units from the camera, before the fog start, so fog did not explain their limited visibility in this fixture. The current chase view exposes only a few small, partly occluded vent surfaces. The target remains as selected; C1 should treat racing-distance readability as a primary A/B go/no-go question. These measurements cover one desktop chase state and do not establish visibility across all sectors, portrait view, rear view, or physical devices.

Evidence: [unmodified chase screenshot](undercity-chase-desktop-1920x1080.png), [machine-readable visibility report](vent-chase-visibility.json). The screenshot SHA-256 is recorded in the JSON. The report describes ray-sample occlusion, not pixel contribution or device performance.

**If structural ribs are required:** choose explicitly between texturing the entire `undercity-industrial-architecture` batch and splitting the 32 facade-rib instances into their own batch. The first affects foundations, roof units, ribs, and loading-bay doors together. The second adds a separate batch/draw and requires new accounting against the existing graphics budgets. Neither choice is made here.

The dedicated visibility screenshot was captured for this C0 checkpoint. No material was applied, and no performance certification was performed.
